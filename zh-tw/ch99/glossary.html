附錄 B — 術語表

最近更新日期

2026-09-12

本術語表收錄全書使用的重要技術術語及其英文對照。

A

Allocation（記憶體配置）

在記憶體中劃分空間給物件使用的過程，也稱 memory allocation；在 .NET 效能討論中，常指 Heap Allocation。可能會造成 GC 壓力。

Anemic Domain Model（貧血模型）

一種 domain model 設計上的反模式（anti-pattern）。它看起來像 domain model，擁有 Order、Customer、Invoice 這類領域名詞，也保存了相關資料；但物件本身幾乎沒有行為，業務規則散落在 controller、service、UI handler 或 repository 等其他地方。結果是模型無法保護自己的狀態，任何地方只要拿到物件，就可能繞過必要的驗證或狀態轉換規則。

貧血模型的問題不只是「方法沒有放在資料型別裡」，而是業務規則沒有被集中、清楚、可靠地表達。如果資料型別本身保持單純，但所有狀態轉換都集中在明確的 workflow、domain service 或其他目的明確的模組中，這不一定等於貧血模型；反之，如果規則散落各處，即使專案裡有許多 service，也很容易讓狀態變得難以追蹤與維護。

參考：Anemic Domain Model（Martin Fowler）

AOT（Ahead-of-Time，預先編譯）

將程式碼直接編譯成原生機器碼（Native Code）的技術，不依賴執行時期的 JIT 編譯。

Application layer（應用程式層）

負責協調一個應用流程所需的外部依賴與執行順序，例如讀取資料、取得目前時間、呼叫外部服務、以及儲存結果。Application layer 通常把取得的普通資料交給 domain model 處理，而不在這一層重複實作核心業務規則。

Asynchronous programming（非同步程式設計）

不需要等待作業完成即可繼續執行後續程式碼的設計模式，常用於提升應用程式的反應能力與吞吐量。

Attribute

附加在型別、方法、屬性等程式碼元素上的宣告式標記（如 [NotNull]、[Obsolete]），用來提供額外的中繼資料（metadata）或改變編譯器行為。本書直接使用英文 “Attribute” 而不翻譯，以避免與 property（屬性）混淆。

B

Boilerplate code（樣板程式碼）

為了達成某些功能而必須重複撰寫的標準化程式碼，例如 INotifyPropertyChanged 的實作。

Boxing（裝箱）

將 value type 轉換為 object（reference type）的過程，會在 heap 上配置記憶體。

Buffer（緩衝區）

用來暫存資料的記憶體區塊，通常是陣列或記憶體片段。

C

CLI（command line interface）

命令列介面。一種透過文字指令與電腦互動的使用者介面。

CLR（common language runtime）

通用語言執行環境。.NET 的執行時期環境，負責執行編譯後的 IL 程式碼。

Closure（閉包）

能夠捕獲（capture）並記憶其建立時所在作用域之變數（外部變數）的函式。

Collection Expression（集合運算式）

C# 12 引入的統一集合初始化語法，使用 [] 符號。支援陣列、List、Span 等類型的建立與初始化。

Constructor（建構式）

類別或結構中的特殊方法，用於初始化物件。建構式的名稱與類別名稱相同，且沒有回傳型別。

Context switch（環境切換）

CPU 從一個執行緒切換到另一個執行緒的過程，保存與恢復執行狀態需要時間，有其效能成本。

Cooperative cancellation（協同式取消）

作業主動檢查是否收到取消請求（透過 CancellationToken）並停止執行的機制，而非由外部強制終止。

D

Deadlock（死結）

兩個或多個執行緒互相等待對方釋放資源，導致程式無法繼續執行且無法恢復的狀態。

Dispose（釋放）

明確釋放資源的動作，通常透過實作 IDisposable 介面來達成。

Deferred Execution（延遲執行）

LINQ 查詢的特性，查詢在建立時不會立即執行，而是在實際需要結果時才執行。

Delegate（委派）

一種型別安全的函式指標，可儲存對方法的參考，並在稍後呼叫該方法。是事件與回呼機制的基礎。

Data Transfer Object (DTO)（資料傳輸物件）

用來在系統邊界或層與層之間傳遞資料的物件，例如 API request DTO、response DTO。DTO 的主要職責是承載資料，不應包含業務邏輯。

Domain Factory（領域工廠）

負責以受控方式建立 domain model 的方法或型別。它可以集中檢查建立物件時必須成立的業務規則，避免呼叫端直接建立不合法的狀態。

Domain Model（領域模型）

用程式型別表達核心業務概念、狀態與規則的模型。例如訂單系統中的 Order、OrderLine、與訂單狀態轉換。使用 domain model 這個名稱，不代表系統必須採用完整的領域驅動設計（DDD）。

E

Enumerator（列舉器）

實作 IEnumerator<T> 介面的物件，用於巡訪序列中的元素。提供 MoveNext() 和 Current 等方法。

Event（事件）

類別或物件用來通知其他類別或物件發生了某些事情的機制。基於委派實作的發布／訂閱模式。

Extension Method（擴充方法）

一種靜態方法，透過 this 關鍵字修飾第一個參數，使其能像實例方法一樣被呼叫。C# 3.0 引入，是 LINQ 的基礎。

Expression Tree（運算式樹）

將程式碼表示為樹狀資料結構。IQueryable<T> 使用運算式樹來儲存查詢邏輯，以便轉換為其他查詢語言（如 SQL）。

Exception（例外）

程式執行期間發生的錯誤或異常狀況。在 .NET 中，所有例外都繼承自 System.Exception。

Exception Filter（例外篩選器）

使用 when 關鍵字來篩選 catch 區塊捕捉的例外，比在區塊內重新拋出更有效率。

F

Finalizer（終結器）

物件被垃圾回收（GC）前由執行環境呼叫的特殊方法，用於釋放非託管資源（unmanaged resource）。在 C# 中使用 ~ClassName 語法宣告。

Fluent API（流暢介面）

一種 API 設計風格，透過方法鏈（method chaining）讓程式碼讀起來更接近自然語言。常與擴充方法搭配使用。

Fragmentation（碎片化）

記憶體中有許多細小的閒置空間，卻無法配置大塊連續記憶體的現象，常見於 Large Object Heap。

G

GC（garbage collector）

垃圾回收器。自動管理記憶體配置與釋放的機制。

Guard clause（防衛子句）

在函式開頭提早檢查（例如檢查參數是否為 null）並返回，避免錯誤擴散或巢狀縮排過深。

H

Heap（堆積）

用於存放物件與較大資料的記憶體區域，由 GC 管理。

Heap Allocation（堆積配置）

在記憶體的堆積（Heap）區塊配置物件，需要 GC 回收。過多的堆積配置會增加 GC 壓力。

Hot path（熱點路徑）

程式中被極度頻繁執行的程式碼路徑，是效能優化的首要目標。

I

IL（intermediate language）

中介語言。C# 原始碼編譯後的中間格式，由 CLR 執行。

Immutable collection（不可變集合）

修改時會回傳新集合的資料結構（如 ImmutableList<T>），原集合內容不變。

Immutable（不可變）

物件一旦建立後，其內容就無法被修改的特性。例如 string。

Init accessor（init 存取子）

C# 9 引入的屬性存取子，限制屬性只能在物件初始化時賦值，確保不可變性。

Iterator（迭代器）

使用 yield return 語法建立的序列產生器，能夠依需求逐個產生值，支援延遲執行。

Inner Exception（內部例外）

引發當前例外的原始例外，通常保存在 InnerException 屬性中，用於保留錯誤的原始脈絡。

Invariant（不變條件）

物件或模型在有效狀態下必須永遠滿足的規則。例如訂單必須至少有一個項目，或只有已提交的訂單才能付款。建立物件與執行狀態轉換時，都不應讓結果違反這些規則。

L

Large Object Heap (LOH)（大型物件堆積）

專門存放大型物件（>= 85,000 bytes）的區域，較少進行重組（compaction），容易產生碎片。

Local Method（區域方法）

定義在另一個方法內部的輔助方法。可以存取外層方法的變數，常用於封裝僅在該方法內使用的邏輯。

Lazy Evaluation（惰性求值）

與延遲執行相同，強調「需要時才計算」的特性。LINQ 查詢就是採用惰性求值。

Lambda expression（Lambda 運算式）

一種用來建立匿名函式的簡潔語法。可包含運算式或陳述式區塊，常用於建立委派或運算式樹。

LINQ（Language Integrated Query）

語言整合查詢。C# 的強大特性，將查詢能力直接整合到語言中，可用於查詢記憶體集合、資料庫、XML 等資料來源。

LINQ Provider（LINQ 提供者）

針對特定資料來源實作的 LINQ 引擎，如 LINQ to Objects、LINQ to Entities 等。

M

Managed Heap（託管堆積）

受 GC 管理的記憶體區域，存放參考型別物件。

Managed Resource（託管資源）

由 CLR（主要是 GC）自動管理的資源，如記憶體中的物件。相對的是 Unmanaged Resource。

Materialization（具體化）

使用 ToList()、ToArray() 等方法立即執行 LINQ 查詢並將結果儲存為實體集合。

Method Syntax（方法語法）

LINQ 的一種撰寫方式，使用擴充方法串接來表達查詢，也稱為串接語法（fluent syntax）。

N

Non-positional record（非位置式 record）

本書用來和 positional record 對照的說法，指使用一般屬性語法宣告屬性、建構式與驗證邏輯的 record 寫法。有些資料也會稱為 nominal record。適合需要驗證、預設值或較複雜建構流程的型別。

Null（空值）

表示「無值」或「不存在」的特殊值。Tony Hoare 稱其為「十億美元錯誤」。

Nullable Reference Type (NRT)（可為 null 的參考型別）

C# 8+ 引入的特性，讓編譯器能夠在編譯時期檢查參考型別的 null 安全性。

Nullable Value Type（可為 null 的實值型別）

透過 T? 語法（如 int?），讓實值型別也能表達「無值」狀態。

Null coalescing operator（Null 聯合運算子）

符號為 ??，用於提供 null 時的預設值。

Null coalescing assignment operator（Null 聯合指派運算子）

符號為 ??=（C# 8+），當變數為 null 時才賦值。

Null conditional operator（Null 條件運算子）

符號為 ?. 和 ?[]，安全地存取可能為 null 的物件成員或索引。

Null conditional assignment（Null 條件指派）

C# 14 引入的語法，允許 ?. 出現在指派運算子左側（如 obj?.Prop = val），僅在物件非 null 時賦值。

Null-forgiving operator（Null 寬容運算子）

符號為 !，告訴編譯器「我確定這裡不是 null」。應謹慎使用。

NullReferenceException（Null 參考例外）

當嘗試存取 null 物件的成員時拋出的異常，是最常見的執行時期錯誤之一。

O

Object initializer（物件初始設定式）

C# 建立物件時用大括號設定屬性或欄位的語法，例如 new Customer { Name = "Alice" }。常與 init 存取子搭配，用來在物件建立階段設定不可變資料。

Object-relational mapping (ORM)（物件-關聯對應）

將程式中的物件模型與關聯式資料庫的資料表、欄位互相對應的技術。實務上也常用 ORM 指稱提供這種能力的工具或框架，例如 Entity Framework Core。

P

Partial class / method（部分類別 / 方法）

允許將類別或方法的定義分散在多個檔案中。這是 Source Generator 能夠注入程式碼的基礎。

Pattern matching（模式比對）

現代 C# 的語法特性，提供更清晰的型別檢查、屬性解構與邏輯判斷方式。

  • Type Pattern：檢查變數是否為特定型別。
  • Constant Pattern：檢查變數是否等於某個常數。
  • Relational Pattern：使用 <、> 等運算子進行比較。
  • Logical Pattern：使用 and、or、not 組合模式。
  • Property Pattern：檢查物件的屬性值。
  • Positional Pattern：根據位置解構物件。
  • List Pattern：檢查序列的結構與元素。
  • Discard Pattern：使用 _ 忽略不關心的部分。
  • Var Pattern：將比對結果指派給變數。

Persistence Entity（持久化實體）

配合資料庫結構或資料存取工具使用的儲存模型。它可能需要可寫入的屬性、建構式或 mapping 設定，不一定和執行業務規則的 domain model 使用相同型別。

Positional record（位置式 record）

將主要資料成員直接寫在 record 型別名稱後方小括號中的宣告方式，例如 public record Money(decimal Amount, string Currency);。適合屬性少、資料形狀明確的 DTO 或 value object。

相關詞彙：Non-positional record（非位置式 record）

Primary constructor（主要建構式）

C# 12 引入的語法，允許在類別或結構宣告時直接定義建構式參數。

Projection（投影）

LINQ 中將資料轉換為另一種形狀的操作，通常使用 Select 方法。

Q

Query Syntax（查詢語法）

LINQ 的一種撰寫方式，使用 from、where、select 等關鍵字，語法類似 SQL。

R

Race condition（競爭狀況）

多個執行緒同時存取共享資源，導致結果不可預測的錯誤。

Range Variable（範圍變數）

在 LINQ 查詢語法中，from 子句定義的變數，代表資料來源中的每個元素。

Record（記錄型別）

C# 9 引入的參考型別（C# 10 支援 record struct），專為不可變資料設計，提供值相等性與簡潔語法。

常見寫法包含 positional record（參見 P 字部）與 non-positional record（參見 N 字部）。

Reference type（參考型別）

另一種說法是「參考類型」。儲存記憶體位址（reference）的型別，包括 class、interface、delegate、record 等。

Reflection（反射）

在執行時期動態檢查型別資訊、成員方法與屬性的技術。功能強大但效能開銷較大。

Repository（儲存庫）

提供讀取與儲存資料操作的抽象，讓呼叫端不必知道底層使用 Entity Framework Core、其他 ORM、Dapper、手寫 SQL、或其他儲存方式。具體介面與責任應依系統需求決定，不必為了採用不可變資料而固定成某一種實作。

Required modifier（required 修飾詞）

C# 11 引入的關鍵字，強制使用者在物件初始化時必須設定該屬性或欄位。

S

Scope（作用域）

變數可以被存取的程式碼範圍。

Sequence（序列）

可循序、單向存取的資料結構，由 IEnumerable<T> 和 IEnumerator<T> 定義。每次只能取得當前元素。

Slicing（切片）

建立指向現有記憶體區塊之子集的操作（如 Span<T>.Slice），不需複製資料，極具效能優勢。

Source Generator（來源產生器）

在編譯時期動態產生 C# 原始碼的編譯器功能，可取代部分 Reflection 與樣板程式碼。

Span

代表一段連續記憶體的結構（Span<T>），支援陣列、Stack 與原生記憶體，是高效能操作的核心。

Stack（堆疊）

用於存放區域變數與方法呼叫上下文的記憶體區域，存取速度極快但空間有限。

Standard Query Operators（標準查詢運算子）

標準查詢運算子（Standard Query Operators）。LINQ 提供的一組擴充方法，如 Where、Select、OrderBy 等，用於查詢和操作序列。

Structural Equality（結構相等）

根據物件的結構與內容（屬性值）來判斷是否相等，而非依據記憶體位址。

Structural Sharing（結構共享）

不可變集合內部使用的優化技術，在建立新版本集合時共用既有的節點，以節省記憶體。

State machine（狀態機）

編譯器為 async 方法或 yield 迭代器產生的隱藏類別/結構，用來記錄執行狀態與變數，以實現暫停與恢復執行。

String Interpolation（字串插補；字串插值）

允許在字串中直接嵌入運算式的語法（如 $"Hello, {name}"），編譯器會自動將其轉換為字串拼接或格式化操作。

Stack Trace（堆疊追蹤）

顯示例外發生時的方法呼叫堆疊資訊，用於追蹤錯誤發生的路徑。

Stack Unwinding（堆疊展開）

例外發生時，執行環境會逐層往上尋找合適的例外處理器（catch block）的過程。

Switch expression（Switch 運算式）

C# 8+ 引入的簡潔語法，使用模式比對來回傳值，是傳統 switch 陳述式的現代替代品。

Synchronization context（同步環境）

用來控制非同步程式碼在恢復執行時應該回到哪個執行緒的機制（如 UI 執行緒、ASP.NET Request 執行緒）。

Syntactic sugar（語法糖）

簡化程式語法的機制，編譯後會還原成較複雜的底層程式碼。例如 async/await、using 陳述式。

Tester-Doer Pattern（測試者-執行者模式）

一種 API 設計模式。提供一個測試方法（如 CanRead）和一個執行方法（如 Read），讓呼叫者先檢查再執行，避免例外。

Try-Parse Pattern (TryXxx 模式)

一種 API 設計模式。與 Tester-Doer 類似，但將檢查與執行合併（如 TryParse），回傳 bool 表示成功與否。

T

Thread pool（執行緒池）

系統預先建立並管理的執行緒集合，用來重複利用執行緒資源，避免頻繁建立與銷毀執行緒的成本。

Top-level statements（頂層語句）

C# 的現代語法特性，允許在 Program.cs 中直接撰寫程式碼，而不需要明確定義 class 和 Main 方法。

U-Z

Unboxing（拆箱）

將 object 轉回 value type 的過程。

Unmanaged Resource（非託管資源）

不受 CLR 管理的資源，如檔案控制代碼（file handles）、視窗控制代碼（window handles）、網路連線等，需手動釋放。

Using Declaration（using 宣告）

C# 8 引入的語法，不需要大括號即可在變數離開作用域時自動釋放資源。

Value type（實值型別）

另一種說法是「值類型」。直接包含資料的型別，包括所有數值型別、bool、char、enum、struct 等。

Value Equality（值相等性）

同 Structured Equality。根據屬性值判斷相等。

Value object（值物件）

以內容值而非物件識別來判斷相等性的物件，常用於表達領域中的小型概念，例如金額、地址或電子郵件。Value object 通常設計為不可變。

With expression（With 運算式）

C# 9 引入的語法，用於建立不可變物件的複本並修改部分屬性（非破壞性修改）。

Zero runtime overhead（零執行時期開銷）

功能的運作不會在程式執行當下增加額外的資源負擔。Source Generator 透過將工作移至編譯時期來達成此目標。
