關於本書

修改於

2026-09-12

本書介紹如何在 C# 中運用不可變資料設計（immutable data design），降低可變狀態在程式中流動時帶來的推理成本。你會看到如何使用 record、init、required、with 運算式、不可變集合與模式比對，把「修改物件」改寫成更容易追蹤、測試與維護的資料轉換。

本書不是要你放棄物件導向，也不是要把所有程式碼都改成函數式風格。相反地，它關注的是更務實的問題：在現有 C# 專案中，哪些資料適合保持不可變？哪些地方仍然應該保留可變物件？當資料需要跨越 API、資料庫、背景流程與測試案例時，怎樣的型別設計能讓程式碼更可靠？

目標讀者

本書適合已經具備 C# 開發經驗，並希望改善資料模型設計、API 設計與狀態管理方式的開發者。你不需要熟悉函數式程式設計，也不需要有進階型別理論背景，但應該已經了解 class、interface、nullable reference types、LINQ，以及 async/await 的基本用法。

你也不需要預先熟悉領域驅動設計（Domain-Driven Design, DDD）或特定的分層架構。本書會使用 domain model、application layer、repository 等常見名稱來說明不同程式碼的責任；這些概念會在第一次實際使用時簡短說明。若你曾接觸 Web API 與資料存取程式碼，閱讀相關範例會更容易，但這不是必要條件。

如果你曾經遇過以下情況，本書會特別有幫助：

  • 一個物件被多個方法或服務改來改去，最後很難確認資料是在哪裡被改壞的。
  • 知道 record、init、with 等語法，但不確定它們在設計上真正解決什麼問題。
  • 想讓 DTO、domain model、事件資料或查詢結果更容易測試與追蹤。
  • 想在不可變設計與現實框架限制之間取得平衡，例如 ORM、序列化、UI 資料繫結或效能敏感程式碼。

本書特色

本書以實務設計判斷為主，不把不可變資料當成單一教條。每個主題都會從常見的可變物件寫法開始，逐步改寫成更清楚的資料模型，並討論這樣做帶來的好處與代價。

本書的主要特色包括：

  • 以 C# 14 與 .NET 10 為基準：範例使用現代 C# 語法與標準函式庫，必要時會說明舊版 C# 或 .NET 的替代做法。
  • 從設計問題出發：不只介紹語法，而是說明何時該用 record、何時該用 class、何時該保留可變物件。
  • 重視可測試性與可追蹤性：透過不可變資料，讓狀態轉換更明確，也讓測試更容易驗證。
  • 討論限制與取捨：不可變資料不是免費的。本書也會說明效能、ORM、UI 資料繫結與深層資料更新等現實問題。
  • 提供完整範例程式：書中的程式碼可搭配 GitHub 範例專案閱讀與實作。

閱讀方法

建議依序閱讀第 1 至第 5 章：前三章建立不可變資料與資料轉換的核心觀念，第 4 章示範最容易落地的 DTO 與資料合約，第 5 章整理適用場景、成本和漸進導入方式。至此已構成完整的核心閱讀路徑。第 6 章是進階選讀，只有在 enum、旗標與 nullable 欄位已經讓狀態難以管理時才需要閱讀。

閱讀程式碼時，請特別留意每個範例想要呈現的設計意圖，而不只是語法本身。不可變資料設計的重點不在於把所有屬性都改成唯讀，而是在於讓資料的生命週期、狀態轉換與使用責任更清楚。

若你想搭配實作練習，可以先下載本書的範例程式，照著章節中的改寫步驟逐步執行測試。建議每讀完一章，就回頭檢查自己的專案中是否有類似的資料模型或狀態轉換流程。你不需要做到最後一個層次才算採用不可變設計；只要讓一組 DTO、一個 value object 或一段資料流程更可靠，就已經得到實際收益。

閱讀裝置建議：建議優先使用電腦或平板來閱讀本書，以獲得較佳的程式碼與圖表閱讀體驗。若使用電子書閱讀器，則建議選擇較大尺寸的裝置。

書寫慣例

有些術語若翻成中文反而容易失真或增加理解成本，因此本書會視情況保留英文，例如 SynchronizationContext、ThreadPool、ExecutionContext 等名詞。第一次出現時通常會以中英並呈，之後則視上下文採用較自然、較不妨礙閱讀的寫法。
